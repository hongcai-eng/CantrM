# 数据权限问题修复说明

## 问题描述
删除岗位后重新创建，分配用户时，如果岗位的数据权限设置为"本组织合同"，但分配时**未指定组织**，用户将无法读取到本组织的合同数据。

## 问题根源

### 数据权限逻辑（app.py 第264-285行）
```python
# 本组织合同权限
if data_scope == 'org':
    # 获取用户的主组织
    user_orgs = UserOrganization.query.filter_by(user_id=user_id, is_primary=True).all()
    org_ids = [uo.organization_id for uo in user_orgs]
    
    if not org_ids:
        # 如果用户没有主组织，则只能看自己创建的和负责的合同
        return [...]
    
    # 返回用户主组织的所有合同
    return Contract.query.filter(
        Contract.organization_id.in_(org_ids)
    ).all()
```

**关键点**：
- 如果岗位数据权限是"本组织合同"（org）
- 但用户的 `UserPosition` 记录中 `organization_id` 为 `None`
- 系统找不到用户的主组织
- 用户只能看到自己创建和负责的合同

## 解决方案

### 已实施的修复（app.py 第1408-1412行）
```python
# 新增：如果岗位的数据权限是"本组织合同"，但未指定组织，给出提示
if position.data_scope == 'org' and not org_id:
    flash(f'岗位"{position.name}"的数据权限为"本组织合同"，必须指定所属组织，否则用户无法访问组织数据', 'warning')
    return redirect(url_for('positions'))
```

**效果**：
- ✅ 强制要求为"本组织合同"权限的岗位指定组织
- ✅ 防止分配用户时遗漏组织信息
- ✅ 给出明确的错误提示

## 使用说明

### 正确的操作流程
1. 创建岗位，设置数据权限为"本组织合同"
2. 分配用户时，**必须选择"所属组织"**
3. 勾选"设为主岗位"（推荐）
4. 保存后，用户可以看到该组织的所有合同

### 错误操作（已被阻止）
1. 创建岗位，设置数据权限为"本组织合同"
2. 分配用户时，**不选择组织**
3. 系统提示："必须指定所属组织，否则用户无法访问组织数据"
4. 分配失败，需要重新选择组织

## 其他可能的问题

### 问题1：用户已有岗位但无主组织
**症状**：用户有岗位，但看不到组织合同

**原因**：旧数据中 UserPosition.organization_id 为 None

**解决**：
1. 进入"岗位管理" → "分配用户"
2. 移除该用户的岗位
3. 重新分配，选择组织

### 问题2：删除组织后数据丢失
**症状**：删除组织后，用户无法访问数据

**原因**：UserPosition.organization_id 指向已删除的组织

**解决**：
1. 删除组织前，先移除组织内的所有用户岗位
2. 或者重新为用户分配岗位和组织

## 总结

**修改内容**：
- 文件：`app.py` 第1408-1412行
- 逻辑：强制验证"本组织合同"权限的岗位必须指定组织
- 效果：防止数据权限配置错误

**使用建议**：
- 为"本组织合同"权限的岗位分配用户时，务必选择组织
- 建议勾选"设为主岗位"，确保组织归属明确
- 删除岗位前，先移除所有用户
