# 修改记录补充4 - 组织层级权限 2026.07.13

## 需求描述

租户用户总管理员要求：在组织管理界面下，项目部下分多个部门/分部/下级机构，**所有项目部下级机构的合同都归项目部统一管理**。

## 业务场景

### 组织结构示例（租户3）
```
项目部（组织17）
├── 付伟龙项目（组织18）- 7条合同
├── 王薇项目（组织19）- 2条合同
└── 梁靓项目（组织20）- 0条合同
项目部本身 - 2条合同
```

### 期望行为
如果用户被分配到"项目部"岗位，应该能看到：
- 项目部本身的2条合同
- 付伟龙项目的7条合同
- 王薇项目的2条合同
- 梁靓项目的0条合同
- **总计：11条合同**（实际9条进行中+2条其他状态）

### 修改前
用户只能看到直接分配给"项目部"（组织17）的2条合同，看不到下级组织的9条合同。

### 修改后
用户能看到项目部及所有下级组织的合同，支持多级组织层级结构。

## 实现方案

### 核心思路
在"本组织合同"（`data_scope='org'`）权限模式下，查询合同时不仅包含用户所在组织，还包含**所有下级组织**。

### 技术实现

#### 1. 新增组织层级查询函数
```python
def get_organization_with_children(org_id):
    """
    递归获取组织及其所有下级组织的ID列表
    参数: org_id - 组织ID
    返回: [org_id, child1_id, child2_id, ...] 包含自身和所有后代
    """
```

使用递归算法：
1. 将当前组织ID加入结果列表
2. 查询 `parent_id = org_id` 的所有直接子组织
3. 对每个子组织递归调用，获取其下级
4. 返回去重后的完整列表

#### 2. 修改数据权限计算逻辑
在 `get_user_accessible_contract_ids()` 函数中，"本组织合同"部分：

**修改前**：
```python
org_contracts = Contract.query.filter(
    Contract.organization_id.in_(org_ids),  # 仅查询用户所在组织
    Contract.status != '已完结'
).all()
```

**修改后**：
```python
# 扩展组织ID列表，包含所有下级
expanded_org_ids = []
for org_id in org_ids:
    expanded_org_ids.extend(get_organization_with_children(org_id))
expanded_org_ids = list(set(expanded_org_ids))  # 去重

# 查询本组织及所有下级组织的合同
org_contracts = Contract.query.filter(
    Contract.organization_id.in_(expanded_org_ids),
    Contract.status != '已完结'
).all()
```

## 适用场景

### ✅ 支持的组织结构
- 两级：总部 → 分公司
- 三级：总部 → 分公司 → 部门
- 多级：总部 → 大区 → 分公司 → 部门 → 小组
- 递归深度无限制

### 🔍 注意事项
1. **只影响"本组织合同"权限**：数据范围为 `org` 的岗位才会启用层级查询
2. **不影响其他权限模式**：`all`（全部）、`self`（仅自己）、`custom`（自定义）不变
3. **已完结合同的特殊规则**：只有原负责人/创建人能看到，不随组织层级显示
4. **性能考虑**：递归查询在组织层级较深时可能影响性能，建议层级不超过5级

## 业务价值

1. **简化权限管理**：只需分配到父级组织，自动获得所有下级权限
2. **支持灵活的组织结构**：适应企业实际的多层级管理需求
3. **保持权限一致性**：组织调整后，权限自动跟随组织结构变化
