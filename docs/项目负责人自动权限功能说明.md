# 项目负责人自动权限功能说明

## 功能概述

从现在开始，**合同的项目负责人自动拥有该合同的所有操作权限**，无需额外分配岗位或配置权限。

## 实现原理

### 新增函数：`has_permission_for_contract(user_id, permission, contract)`

这个函数扩展了原有的权限检查逻辑：

```python
def has_permission_for_contract(user_id, permission, contract):
    """
    检查用户是否对特定合同拥有指定的功能权限
    项目负责人自动拥有该合同的所有权限
    """
    user = User.query.get(user_id)
    
    # 1. 检查是否是该合同的项目负责人
    if contract and contract.project_staff and user.username in contract.project_staff:
        return True  # 项目负责人拥有所有权限
    
    # 2. 否则检查常规权限（用户权限 + 岗位权限）
    return has_permission(user_id, permission)
```

### 权限检查优先级

1. **项目负责人检查**（最高优先级）
   - 如果用户名出现在合同的 `project_staff` 字段中
   - 自动拥有该合同的所有操作权限
   - 无需任何岗位或权限配置

2. **常规权限检查**
   - 用户自身的 `permissions` 字段
   - 用户所有岗位的 `function_permissions` 字段
   - 超级管理员权限

## 权限说明

### 项目负责人拥有的权限

对于自己负责的合同，项目负责人自动拥有：
- ✅ 查阅 - 查看合同详情
- ✅ 修改 - 编辑合同信息
- ✅ 删除 - 删除合同
- ✅ 增加 - 添加支付/交付/发票记录
- ✅ 上传 - 上传文件
- ✅ 下载 - 下载文件

### 示例场景

**场景1：付伟龙是某合同的项目负责人**
- 合同ID: 4
- 项目名称: 阿特拉斯
- 项目负责人: 付伟龙
- 付伟龙的用户权限: 无
- 付伟龙的岗位: 项目经理（有权限）

**结果**：
- 即使没有岗位权限，付伟龙也能编辑、删除该合同
- 因为他是该合同的项目负责人

**场景2：张三不是该合同的项目负责人**
- 张三的用户权限: 无
- 张三的岗位: 无

**结果**：
- 张三无法操作该合同
- 需要分配相应的岗位或权限才能操作

## 数据权限整合

项目负责人权限与数据权限系统完美整合：

### 数据权限（控制能看到哪些合同）
- **all** - 全部合同
- **org** - 本组织合同
- **custom** - 自定义授权的合同
- **self** - 自己创建的合同 + **自己负责的合同** ← 已整合

### 功能权限（控制能做什么操作）
- 项目负责人：自动拥有该合同的所有操作权限
- 其他用户：根据岗位权限判断

## 向后兼容性

✅ **完全向后兼容**
- 原有的用户权限系统保持不变
- 原有的岗位权限系统保持不变
- 超级管理员权限不受影响
- 只是新增了"项目负责人自动权限"这一层

## 优势

1. **简化管理**
   - 无需为每个项目负责人单独配置权限
   - 项目负责人更换时，只需修改合同的 `project_staff` 字段

2. **符合业务逻辑**
   - 项目负责人理应拥有项目的完整控制权
   - 更符合实际工作流程

3. **灵活性**
   - 可以为同一个合同指定多个项目负责人（逗号分隔）
   - 所有项目负责人都自动获得权限

4. **安全性**
   - 仍然受租户隔离限制
   - 仍然受数据权限范围限制
   - 只是功能权限检查时给予项目负责人特殊待遇

## 使用建议

### 为合同指定项目负责人

在创建或编辑合同时，在"项目负责人"字段填入用户名：
- 单个负责人：`张三`
- 多个负责人：`张三,李四,王五`（逗号分隔）

### 不再需要的操作

- ❌ 不再需要为项目负责人单独创建岗位
- ❌ 不再需要为项目负责人分配权限
- ❌ 不再需要为每个合同授权给项目负责人

### 权限层级

```
用户权限检查流程:
1. 是超级管理员？ → 拥有所有权限
2. 是项目负责人？ → 拥有该合同的所有权限
3. 有用户自身权限？ → 根据配置判断
4. 有岗位权限？ → 根据配置判断
5. 否则 → 无权限
```
