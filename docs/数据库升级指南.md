# 数据库升级指南

## 问题现象
将旧备份的 `contracts.db` 替换到新系统后，系统运行出错。

## 原因分析
新版本代码添加了新字段（如 `tenant_customer.system_name`），但旧数据库中没有这些字段，导致系统报错。

## 解决方案

### 方法一：使用自动升级脚本（推荐）

1. **备份当前数据库**
   ```bash
   cp instance/contracts.db instance/contracts.db.backup
   ```

2. **将旧数据库替换到系统**
   ```bash
   # 将旧的 contracts.db 复制到 instance/ 目录
   cp /path/to/old/contracts.db instance/contracts.db
   ```

3. **运行升级脚本**
   ```bash
   python upgrade_db.py
   ```

4. **重启应用**
   ```bash
   python app.py
   ```

### 方法二：手动执行 SQL

如果升级脚本无法运行，可以手动执行以下 SQL：

```sql
-- 添加租户系统名称字段
ALTER TABLE tenant_customer ADD COLUMN system_name VARCHAR(200);

-- 添加试用期字段（如果不存在）
ALTER TABLE tenant_customer ADD COLUMN trial_expires_at DATETIME;

-- 添加合同业务类型字段（如果不存在）
ALTER TABLE contract ADD COLUMN business_type VARCHAR(20) DEFAULT '销售';

-- 添加客户业务类型字段（如果不存在）
ALTER TABLE customer ADD COLUMN business_type VARCHAR(20) DEFAULT '销售';
```

使用 SQLite 工具执行：
```bash
sqlite3 instance/contracts.db < migrations/add_tenant_system_name.sql
```

## 升级脚本说明

`upgrade_db.py` 会自动检测数据库中缺失的字段并添加，包括：

- `tenant_customer.system_name` - 租户独立系统名称
- `tenant_customer.trial_expires_at` - 试用期截止时间
- `contract.business_type` - 合同业务类型（采购/销售）
- `customer.business_type` - 客户业务类型（采购/销售）

脚本会先检查字段是否已存在，避免重复添加。

## 注意事项

1. **务必先备份**：升级前一定要备份数据库
2. **检查字段**：升级后可以用 `sqlite3 instance/contracts.db ".schema tenant_customer"` 检查字段是否添加成功
3. **版本记录**：每次升级后建议记录升级时间和版本号
