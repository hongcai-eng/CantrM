# 虚拟组织 + 虚拟岗位 + 岗位赋权功能说明

## 功能概述

为系统添加了更灵活的组织和权限管理机制，支持虚拟组织（临时项目组）、岗位模板和精细化的数据权限控制。

## 一、虚拟组织

### 功能说明
虚拟组织是指跨部门的临时项目组，用于临时性工作、专项任务等场景。

### 特点
- **临时性**：用于短期项目或专项任务
- **跨部门**：成员可以来自不同的实体部门
- **灵活性**：项目结束后可以解散或归档
- **标识**：列表中显示 `[虚拟]` 标识，用橙色突出显示

### 使用场景
- 跨部门项目组（如：新产品开发项目）
- 临时工作组（如：年度审计小组）
- 专项任务团队（如：ISO认证工作组）

### 操作方法
1. 进入"组织结构管理"页面
2. 点击"新建组织"
3. 勾选"虚拟组织（跨部门项目组）"复选框
4. 填写组织名称和描述
5. 创建后，可以从不同部门调入人员

## 二、岗位模板

### 功能说明
岗位模板是预定义的角色，包含特定的权限集合，可以分配给用户。

### 岗位属性

#### 1. 基本信息
- **岗位名称**：如"项目经理"、"技术负责人"、"合同审批人"
- **描述**：岗位职责说明

#### 2. 功能权限
控制用户可以执行的系统操作：
- 增加
- 删除
- 修改
- 查阅
- 上传
- 下载
- 导入EXCEL
- 导出EXCEL

#### 3. 数据权限范围
控制用户可以访问的合同数据：
- **全部合同**：可以访问租户内所有合同
- **本组织合同**：只能访问所属组织的合同
- **仅自己创建的合同**：只能访问自己创建的合同
- **自定义**：需要手动指定可访问的具体合同

### 操作方法

#### 创建岗位
1. 进入"岗位管理"页面
2. 点击"新建岗位"
3. 填写岗位名称和描述
4. 选择功能权限（可多选）
5. 选择数据权限范围
6. 点击"创建"

#### 编辑岗位
1. 在岗位列表中找到要编辑的岗位
2. 点击"编辑"按钮
3. 修改相关信息
4. 点击"保存"

#### 删除岗位
1. 在岗位列表中找到要删除的岗位
2. 点击"删除"按钮
3. 确认删除（会同时删除该岗位的所有用户分配和权限授予）

## 三、用户岗位分配

### 功能说明
将岗位分配给用户，用户将继承岗位的所有权限。一个用户可以担任多个岗位。

### 岗位属性

#### 1. 主岗位
- 每个用户可以设置一个主岗位
- 主岗位的权限优先生效
- 用于确定用户的主要职责

#### 2. 组织归属
- 可以指定用户在哪个组织担任该岗位
- 支持跨组织兼任（如：技术部员工在项目组兼任项目经理）
- 不指定组织则全局生效

### 操作方法

#### 为用户分配岗位
1. 在岗位管理页面，找到要分配的岗位
2. 点击"分配用户"按钮
3. 选择用户
4. 选择所属组织（可选）
5. 勾选"设为主岗位"（可选）
6. 点击"分配"

#### 查看用户岗位
在"用户岗位明细"表格中可以看到：
- 每个用户拥有的岗位
- 岗位所属组织
- 主岗位标识

## 四、岗位赋权（合同数据权限）

### 功能说明
为数据权限范围设置为"自定义"的岗位，手动指定可以访问的具体合同。

### 权限类型
- **查看**：只能查看合同详情，不能修改
- **编辑**：可以查看和修改合同

### 操作方法

#### 为岗位授权合同
1. 在岗位管理页面，找到数据权限为"自定义"的岗位
2. 点击"授权合同"按钮
3. 选择要授权的合同
4. 选择权限类型（查看/编辑）
5. 点击"授权"

#### 更新合同权限
- 对已授权的合同再次授权，会更新权限类型
- 例如：将"查看"权限升级为"编辑"权限

## 五、权限计算逻辑

### 权限优先级
1. **超级管理员**：拥有所有权限
2. **岗位权限**：用户通过岗位获得的权限
3. **组织权限**：用户所属组织的权限
4. **用户权限**：用户个人的权限（旧系统）

### 权限合并规则
- 用户拥有的所有岗位的功能权限**合并**（取并集）
- 数据权限按照**最宽松**的范围计算
  - 任一岗位为"全部合同" → 可访问全部
  - 有"本组织" + "自定义" → 可访问本组织和自定义的合同

### 示例

**场景**：张三同时担任两个岗位
- **岗位A（项目经理）**：功能权限=增加,修改,查阅，数据权限=本组织合同
- **岗位B（合同审批人）**：功能权限=查阅,审批，数据权限=全部合同

**结果**：
- 功能权限：增加, 修改, 查阅, 审批（合并）
- 数据权限：全部合同（最宽松）

## 六、典型使用场景

### 场景1：跨部门项目组
1. 创建虚拟组织"XX项目组"
2. 创建岗位"项目经理"（权限：全部功能，数据范围：本组织）
3. 创建岗位"项目成员"（权限：查阅,修改，数据范围：本组织）
4. 从不同部门调入人员到项目组
5. 为项目经理分配"项目经理"岗位
6. 为其他成员分配"项目成员"岗位

### 场景2：合同审批流程
1. 创建岗位"合同审批人"（功能权限：查阅,修改，数据权限：自定义）
2. 为该岗位授权特定的待审批合同
3. 将岗位分配给审批人员
4. 审批人员只能访问被授权的合同

### 场景3：临时权限授予
1. 某员工临时需要访问特定合同
2. 创建临时岗位"XX合同查看"（功能权限：查阅，数据权限：自定义）
3. 为该岗位授权指定合同
4. 将岗位分配给员工
5. 工作完成后，删除岗位或移除用户的岗位分配

## 七、数据库表结构

### 新增表

#### 1. position（岗位表）
- id: 主键
- name: 岗位名称
- description: 描述
- customer_id: 租户ID
- function_permissions: 功能权限（逗号分隔）
- data_scope: 数据权限范围（all/org/self/custom）
- created_at: 创建时间

#### 2. user_position（用户岗位关联表）
- id: 主键
- user_id: 用户ID
- position_id: 岗位ID
- organization_id: 组织ID（可选）
- is_primary: 是否主岗位
- created_at: 创建时间

#### 3. position_contract_permission（岗位-合同权限表）
- id: 主键
- position_id: 岗位ID
- contract_id: 合同ID
- permission_type: 权限类型（view/edit）
- created_at: 创建时间

#### 4. user_organization（用户-组织关联表）
- id: 主键
- user_id: 用户ID
- organization_id: 组织ID
- is_primary: 是否主组织
- created_at: 创建时间

### 修改表

#### organization（组织表）
新增字段：
- is_virtual: 是否虚拟组织（布尔值）

## 八、API路由

### 岗位管理
- `GET /positions` - 岗位管理页面
- `POST /position/create` - 创建岗位
- `POST /position/<position_id>/edit` - 编辑岗位
- `POST /position/<position_id>/delete` - 删除岗位
- `POST /position/<position_id>/assign_user` - 为用户分配岗位
- `POST /position/<position_id>/grant_contract` - 为岗位授权合同
- `POST /user_position/<up_id>/remove` - 移除用户岗位

### 组织管理（增强）
- `POST /organization/create` - 创建组织（支持虚拟组织）
- `POST /organization/<org_id>/edit` - 编辑组织（支持修改虚拟标识）

## 九、注意事项

1. **权限继承**：用户通过岗位获得权限后，即使岗位被删除，用户已执行的操作不会回滚
2. **数据安全**：删除岗位会同时删除所有相关的用户分配和权限授予
3. **性能考虑**：如果岗位数量很多，权限计算可能影响性能，建议合理规划岗位数量
4. **向后兼容**：旧的用户权限系统保留，新用户建议使用岗位系统
5. **租户隔离**：所有岗位、权限都严格按租户隔离，不会跨租户

## 十、后续优化方向

1. **权限缓存**：缓存用户的综合权限，避免每次都重新计算
2. **权限审计**：记录权限变更历史
3. **批量操作**：支持批量分配岗位、批量授权合同
4. **权限报告**：生成用户权限报告、岗位使用情况报告
5. **权限模板**：预定义常用的岗位模板
6. **时限控制**：为岗位分配设置有效期
