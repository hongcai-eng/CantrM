# 修改记录补充2 - 岗位权限同步问题修复 2026.07.13

## 问题诊断

### 用户反馈
修改岗位管理的"功能权限"后，拥有该岗位的用户实际权限没有生效，即使重新登录也不生效。

### 根本原因
系统采用**权限合并模型**：`用户综合权限 = 自身权限 ∪ 岗位权限`（取并集）。

租户3现有用户分析：
- 大多数用户（王薇、付伟龙、文昌松等）的 `permissions` 字段已填充完整的8项权限
- 这些用户的自身权限已经包含全部操作，修改岗位权限不会减少他们的权限
- 只有李丹等少数用户 `permissions=''`，纯靠岗位获得权限

**示例**：
- 付伟龙自身权限：`增加,删除,修改,查阅,上传,下载,导入EXCEL,导出EXCEL`
- 修改岗位权限为只有"查阅"
- 付伟龙的综合权限 = 自身权限 ∪ 岗位权限 = **仍是全部8项**（自身权限未动）

### 解决方案
改为**岗位优先模型**：修改岗位功能权限时，自动清空该岗位所有用户的自身权限，使这些用户的功能权限完全由岗位决定。

## 改动内容

### 涉及文件
- `app.py` - `edit_position()` 函数

### 具体修改
在 `edit_position()` 保存岗位权限后，增加以下逻辑：

1. 查询该岗位下的所有用户（`UserPosition` 表）
2. 遍历这些用户，将 `user.permissions` 设为 `None`（超级管理员除外）
3. 记录受影响用户名单
4. 提示管理员："该岗位 X 名用户的权限已改为完全由岗位控制（张三、李四等）"

### 安全保护
- ✅ 超级管理员的权限不会被清空（`role != '超级管理员'`）
- ✅ 只影响有 `permissions` 字段值的用户（已有自身权限的）
- ✅ 只影响该岗位的用户，不影响其他岗位
- ✅ 提供明确的操作提示

## 验证结果

### 测试场景
用户：付伟龙（合同负责人，user_id=16）
- 初始自身权限：8项完整权限
- 初始岗位权限：8项完整权限
- 初始综合权限：8项
- 能否删除：True

**操作**：管理员将"项目一部经理"岗位权限改为仅"查阅"和"修改"

**结果**：
- 付伟龙自身权限：`None` ✓
- 付伟龙综合权限：仅"查阅"和"修改" ✓
- 能否删除：`False` ✓
- **权限已同步：True** ✓

### 用户体验
修改岗位权限后，该岗位用户：
1. 不需要重新登录，权限立即生效（后端实时查询数据库）
2. 如当前页面的按钮显示未更新，刷新页面即可（前端模板变量）
3. 以后的权限完全由岗位控制，管理员只需修改岗位，不用逐个改用户

## 影响范围

### 数据变化
- 修改岗位权限时，会清空该岗位用户的 `user.permissions` 字段
- 这是**不可逆**的操作（用户原自身权限会丢失）
- 但权限功能不受影响（岗位权限替代了自身权限）

### 适用场景
- ✅ 企业需要统一管理岗位权限，岗位改了用户权限立即生效
- ✅ 用户权限由岗位决定，不需要单独配置每个用户
- ❌ 不适合需要为每个用户单独定制权限的场景（此时不应使用岗位，或不要修改岗位）

## 后续建议

如果未来需要更灵活的权限模型，可以考虑：
1. 在岗位编辑页面增加"同步方式"选项：
   - "合并模式"：保持用户自身权限，岗位权限作为补充
   - "覆盖模式"：清空用户自身权限，完全由岗位控制（当前实现）
2. 提供"权限预览"功能：修改前显示哪些用户会受影响
3. 增加权限历史记录，便于回溯
