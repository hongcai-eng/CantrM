# 完整权限系统实现说明

## 实现概述

根据《虚拟组织和岗位赋权功能说明.md》文档的要求，已完成基于岗位的**功能权限**和**数据权限**的完整实现。用户现在可以通过岗位获得操作权限和数据访问权限。

## 实现的功能

### 1. 功能权限计算（新增）

#### `get_user_function_permissions(user_id)`
获取用户的综合功能权限（用户自身权限 + 所有岗位的功能权限合并）

**返回值**：
- `'all'` - 拥有所有功能权限
- `['增加', '删除', '修改', ...]` - 权限列表

**权限来源**：
1. 用户自身的 `permissions` 字段
2. 用户所有岗位的 `function_permissions` 字段

**合并规则**：取并集（用户拥有的所有权限）

#### `has_permission(user_id, permission)`
检查用户是否拥有指定的功能权限

**示例**：
```python
if has_permission(user_id, '增加'):
    # 用户可以执行增加操作
```

#### `get_user_permissions_string(user_id)`
获取用户权限的字符串表示（用于传递给模板）

**返回值**：
- `'all'` - 所有权限
- `'增加,删除,修改,查阅'` - 逗号分隔的权限列表

### 2. 数据权限计算

#### `get_user_data_scope(user_id)`
计算用户的综合数据权限范围，返回最宽松的权限级别：
- **'all'** - 全部合同（超级管理员或任一岗位有 all 权限）
- **'org'** - 本组织合同（任一岗位有 org 权限）
- **'custom'** - 自定义合同（任一岗位有 custom 权限）
- **'self'** - 仅自己创建的合同（默认权限）

**优先级**：all > org > custom > self

#### `get_user_accessible_contract_ids(user_id, customer_id)`
获取用户可访问的合同ID列表：
- 返回 `None` 表示可访问所有合同（超级管理员或 'all' 权限）
- 返回 `[]` 表示没有可访问的合同
- 返回具体的合同ID列表

**权限逻辑**：
- **all 权限**：返回 None（不过滤）
- **org 权限**：返回用户所属组织的所有合同ID
- **custom 权限**：返回岗位被授权的合同ID + 用户自己创建的合同ID
- **self 权限**：返回用户自己创建的合同ID

## 权限检查流程

每个路由的权限检查按以下顺序执行：

1. **登录检查** - `@login_required` 装饰器
2. **功能权限检查** - `@permission_required('操作')` 装饰器
3. **租户隔离检查** - 确保只能访问本租户的数据
4. **数据权限检查** - 基于岗位的数据范围过滤

### 示例代码

```python
@app.route('/contract/<int:id>')
@login_required
def view_contract(id):
    contract = Contract.query.get_or_404(id)

    # 租户隔离检查
    customer_id = get_current_customer_id()
    if customer_id is not None and contract.customer_id != customer_id:
        flash('权限不足', 'warning')
        return redirect(url_for('index'))

    # 数据权限检查
    user_id = session.get('user_id')
    if user_id and customer_id is not None:
        accessible_ids = get_user_accessible_contract_ids(user_id, customer_id)
        if accessible_ids is not None and id not in accessible_ids:
            flash('您没有权限查看该合同', 'warning')
            return redirect(url_for('index'))

    return render_template('contract_detail.html', contract=contract, view_only=True)
```

## 权限合并规则

当用户拥有多个岗位时：
- **功能权限**：取并集（所有岗位的功能权限合并）
- **数据权限**：取最宽松的范围（按优先级 all > org > custom > self）

### 示例

**用户"张三"同时担任两个岗位**：
- **岗位A**：数据权限=本组织合同
- **岗位B**：数据权限=全部合同

**结果**：张三可以访问全部合同（最宽松原则）

## 特殊情况处理

### 1. 没有可访问合同的情况
当用户没有任何可访问的合同时：
- 合同列表显示为空
- 统计数据为 0
- 导出时提示"没有可导出的合同数据"

### 2. 超级管理员
- 系统超级管理员（admin、superadmin）自动拥有所有权限
- 不受数据权限限制
- `get_user_accessible_contract_ids()` 返回 None（不过滤）

### 3. 没有分配岗位的用户
- 默认只能访问自己创建的合同（'self' 权限）
- 不能访问其他用户创建的合同

### 4. 组织权限但未分配组织
- 如果用户岗位有 'org' 权限但未分配到任何组织
- 降级为 'self' 权限（只能看自己创建的合同）

### 5. 自定义权限
- 用户可以访问岗位被明确授权的合同
- 同时也能访问自己创建的合同（两者取并集）

## 数据库依赖

本功能依赖以下数据表：

- `user_position` - 用户岗位关联表
- `position_contract_permission` - 岗位合同权限表
- `user_organization` - 用户组织关联表
- `organization` - 组织表

确保数据库已执行 `upgrade_db_virtual_org_position.py` 升级脚本。

## 性能考虑

### 当前实现
- 每次请求都会查询用户的岗位和权限
- 对于大量合同的查询，使用 `IN` 子句过滤

### 优化建议（未来）
1. **权限缓存**：将用户的综合权限缓存到 session 或 Redis

3. **数据库索引**：为 `contract.created_by` 和 `contract.organization_id` 添加索引

## 测试建议

### 测试场景

1. **超级管理员**
   - 应该能看到所有合同

2. **全部合同权限（all）**
   - 创建岗位，数据权限=全部合同
   - 分配给用户
   - 用户应该能看到租户内所有合同

3. **本组织合同权限（org）**
   - 创建岗位，数据权限=本组织合同
   - 创建组织A和组织B
   - 将用户分配到组织A
   - 为组织A和组织B分别创建合同
   - 用户应该只能看到组织A的合同

4. **自定义权限（custom）**
   - 创建岗位，数据权限=自定义
   - 创建多个合同
   - 为岗位授权其中2个合同
   - 用户应该只能看到被授权的2个合同 + 自己创建的合同

5. **仅自己创建的合同（self）**
   - 用户没有分配任何岗位
   - 用户应该只能看到自己创建的合同

6. **多岗位权限合并**
   - 用户同时拥有 org 和 custom 两个岗位
   - 应该取最宽松的权限（org）

7. **批量操作**
   - 选择多个合同进行批量删除
   - 只有权限范围内的合同会被删除
   - 无权限的合同会被跳过
