## 三、改动明细

### 问题1｜合同管理「下一页」无效

- 根因：首页/上一页/下一页/末页链接用 Jinja `replace('page='~page, ...)` 拼接 URL，首次进入时 URL 里没有 `page=` 参数，替换失败，链接指向原页；而「输入页码 GO」用 `searchParams.set`，所以能正常跳转。
- 修复：
  - `index.html`、`contract_archive.html` 的四个翻页按钮由 `<a href=...>` 改为调用新增 JS 函数 `jumpToPage(n)`。
  - 新增 `jumpToPage(pageNum)`：用 `URL.searchParams.set('page', n)` 跳转，逻辑与原 `gotoPage()` 一致。
  - 原 `gotoPage()`、`changePerPage()` 保留不动。

### 问题2｜岗位管理编辑：功能权限回显与实际同步

- 现状：后端 `edit_position` 本就保存并 `commit`，`get_user_function_permissions()` 实时从数据库读取岗位权限（权限已实时生效）。
- 新增后端 API：`GET /api/position/<int:position_id>`（函数 `api_position_detail`），返回岗位当前 `name` / `description` / `function_permissions` / `data_scope`，含租户校验。
- `positions.html`：
  - 抽出共用函数 `applyEditPerms(perms)` 负责勾选回显。
  - `showEditForm` 打开弹窗后额外 `fetch('/api/position/<id>')`，用数据库最新权限重新回显，确保「功能权限栏显示的」与「实际生效的」一致。列表页传入的参数作为兜底。

### 问题3｜合同组织分配「查看合同列表」弹窗增强

- `contract_organization_assignment.html`：重构弹窗渲染逻辑，在「序号」表格上方新增工具栏及分页。
  - 工具栏按钮：
    - **查看**：新窗口打开所有勾选合同的详情页。
    - **调整**：改派单条合同到指定组织，复用现有路由 `assign_single_contract`（未新增后端逻辑）。
    - **筛选**：按合同编号/项目名称/客户名称/项目负责人关键字前端过滤。
  - **每页显示**：下拉选项 10/20/50/100 条，配合首页/上一页/下一页/末页前端分页。
  - 每行新增复选框，支持全选。
  - 通过 Jinja 将已传入的 `organizations` 注入 JS 变量 `ORG_OPTIONS`，供「调整」使用。
  - 原函数 `showOrgContracts` / `showUnassignedContracts` / `closeContractList` 名称保留，内部改为调用共用的 `loadContractList` + `renderContractList`。
  - 备注：「调整」当前用 `prompt` 输入组织 ID 完成改派，以保持精简并复用现有路由。
